# 自适应视觉交接

v4 完整流程：右手抓下半瓶身 → 交给左手 → 左手放入篮子 → 松爪撤离。由 RGB 与机器人 FK 在线估计目标，远处采用相对目标接近，近处保留 6 mm 视觉纠偏；不调用旧 TAMP 抓取、交接或放置宏。

## 启动与复现

```bash
./run relay
```

输出保存在自动生成的 `runs/adaptive-*`，也可传 `--case case.json --output runs/新目录`。v3 平滑基线保留为 `./run relay-v3`。这是独立 skill 入口，首页聊天的旧路由没有被静默替换。

批量复现（新输出目录）：

```bash
.venv/bin/python -B tools/relay_campaign.py \
  --splits skills/bottle_visual/adaptive/evaluation.json \
  --groups heldout stress --output runs/adaptive-check --jobs 3
```

保存后的程序直接运行，无需再次调用 API。每例保留 RGB、阶段帧、实测轨迹和工具记录；只给预声明的代表场景录制完整视频，减少重复渲染。

## 结构与关键改动

| 模块 | 作用 |
| --- | --- |
| program.py | 根据新视觉估计计算接近目标，检查闭爪、抬升和交接证据，执行有限重试与实测位置恢复。 |
| visual_adaptive.py | 在线估计相机投影；缓存同一物理时刻的重复图像；提高 IK 延续精度；检查整个接瓶走廊后选择朝向。 |
| relay_campaign.py | 分开开发、回归、留出和边界压力，冻结代码，初始化与执行失败均计入分母。 |
| relay_report.py | 汇总覆盖位置、完整分母、耗时与实际运动取舍，保留失败与原速视频。 |

没有改变质量、摩擦、控制增益、30 Hz 时钟或原生成功门槛。沿用 v3 的 C2 轨迹及速度/加速度/jerk 规划目标，8 mm 实际到位门槛和夹持证据检查保持。

## 本轮结果

| 阶段 | 完整任务通过 |
| --- | --- |
| 首轮开发 | 22/24 |
| 修订后完整开发重跑 | 24/24 |
| 旧场景配对回归 | 6/6 |
| 未参与调优的新留出 | 40/40 |
| 边界压力 | 10/12 |

本轮 82 个声明条件、110 次仿真执行（包含开发重跑），没有把重放算成新增泛化样本。六个配对场景的耗时中位变化 −19.6%，jerk 的 95 分位变化 −20.6%，RMS 变化 +8.5%；接触尖峰没有全面改善。新留出成功案例耗时约 54–67 秒。

第一轮两个失败暴露了接瓶端点可达但中间路径 IK 失败，修正为整段走廊检查；没有放宽 IK 精度。最终两例边界失败位于瓶位 `[0.54, -0.26]`、相机公共偏角 ±10°，右手固定朝向的精细接近 IK 未收敛，尚未验证替代抓取朝向。

Haiku 进行了 1 次工程程序审阅，调整有界等待并增加阶段标签；接口报告 5,750 token，不包含 Codex 自身用量。底层视觉、控制器、场景测试与审查由工程实现；本轮没有神经网络或强化学习训练。

结果、关键过程与视频：`runs/20261026-adaptive/index.html`；中文记录：该目录的 `记录.md`。每轮 `protocol.json`、`source/`、`events.jsonl` 与模型审查保留完整来源。

## 已验证边界

留出瓶位约 7×9 cm，联合改变公共/独立相机角度、距离、曝光、工具像素测量噪声和首次闭爪指令丢失；相机与接近前的目标在每例任务内固定。离散条件通过，不证明矩形内每一点都可行。

仍限已知直立黑瓶、固定白篮、两路合成 RGB 和虚拟工具标记。没有验证任意物体、移动目标、严重遮挡、物理掉瓶重抓或真机迁移；模型夹爪全行程也不是认证过的真机限位。真实设备没有启动。
