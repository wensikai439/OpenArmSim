## 日常使用

- 左上角是重新绘制的双臂矢量标记。主界面保留目标输入、场景、执行过程；模型职责移入模型设置的高级选项，仅支持执行的工作台不显示它。
- 点击“记录”，可搜索任务或技能、筛选失败；左侧选择记录，右侧查看结果、耗时、控制步数和实际关键帧。原始配置、结果、事件和控制轨迹按需打开。
- 模型回复单独标明来源。调用结束、技能完成、完整任务成功、证据未知保留不同状态。缺少历史开头的续接记录会标明不完整，不会消失或推断为成功。
- 历史帧点击后打开原有大图；场景展开与 Esc 还原、相机切换及窄窗口布局继续可用。

## 代码边界

```text
ui/app.js                  组合已有 API、场景、Agent 与记录界面
ui/index.html              页面结构与双臂矢量图标
ui/workspace.js + .css     布局、导航与运行时状态
ui/agent.js                当前任务交互；按用户目标合并后续调用
ui/activity.js             共用的任务分组、结果标签和安全产物路径
ui/records.js + .css        历史列表、搜索、详情与关键帧；只读请求
harness/records.py          既有归档的轻量摘要，不读写文件、不生成新评分
sim/learning.py            目录接口复用上述摘要，避免浏览器逐个读取全部配置
```

记录直接来自既有 `/api/experiments`、`/api/agent` 和受现有访问控制约束的 `/runs/` 文件。只有选中的记录才读取详情，终态详情在当前页面缓存；没有新数据库或新的文件访问接口。目录沿用最近 60 条执行、最近 20 个对话回合的范围；子任务对应的更早执行可按显式 ID 打开，缺项会保留提示。

共享平台原有的个人目录与浏览器归属不变。它的旧目录接口仍可用；若没有轻量摘要字段，列表使用已有类型和时间，选择后读取原有详情。本次没有同步或重启共享服务器。

## 验证

- `node tools/check_records.mjs`：任务分组、缺失历史、循环引用、状态边界和跨记录／外部图片路径拒绝。
- `.venv/bin/python -B -m unittest harness.records_checks deploy.server.checks`：归档终态、身份绑定、缺失／异常测量、旧可选字段与既有服务器检查。
- 读取现有真实日志，20 个回合归为 10 个用户任务，没有丢回合或重复事件；读取过程中没有修改原数据库。
- 浏览器用既有真实执行记录检查搜索、失败筛选、列表切换、关键帧和大图、原始文件链接；空闲时不显示模型活动状态。

预览使用独立对话数据库和仅本会话的 API 配置。检查材料集中在 `.runtime/ui-preview/revision/`，先前局部动作的原生记录仍保留。本次是界面和记录流程验证，不是新的 LLM 或机器人成功率实验。

## 零词元 Haiku 接入

使用 API 地址 `https://zzq.si/v1`、模型名 `claude-haiku-5-5`。可用模型以该 Key 的 `/v1/models` 返回为准；`haiku-5-5` 不在本次 Key 的模型列表中。不要在仓库、截图或运行记录中保存密钥。

2026-11-01 排查到实际 HTTP 400 原因：网关拒绝该模型的非默认 `temperature`，而工具循环发送了 `temperature=0`。`harness/provider.py` 仅对 `zzq.si` 的这个模型省略此参数，保留图片、工具、上下文、调用预算与原有执行检查。连接测试和任务记录现在显示网关 JSON 中经过脱敏、限长的错误原因，不展示原始响应或请求头。

验证先通过文字连接，再将一张原生相机图与只读工具一起发送，确认返回 `report_scene`。随后在界面原样输入“拿起瓶子”，Haiku 完成 `set_plan → pick → finish`，共 3 次模型请求；原生执行 `20261101-233927-tamp-9ca630` 返回 `primitive_success=true`，确认右手夹持与抬升。该次抓取使用已有仿真几何 TAMP 工具；它是单次接入与执行验证，不能作为视觉泛化、基准成功率或真机结果。脱敏证据：`.runtime/ui-preview/haiku.json`。

相关检查：`.venv/bin/python -B -m unittest harness.provider_checks harness.model_checks harness.workspace_checks harness.runtime_composition_checks`，共 48 项通过。

## 输入与执行状态

发送按钮、模型标记与调用状态使用统一的 SVG 线条图标。Enter 发送，Shift+Enter 换行；输入法选词时按 Enter 不提交任务，长按 Enter 不会重复发送。

异步技能返回 `state=started` 只说明请求被接受。对话与历史记录按原始 `execution_id` 关联同一职责、同一任务的已有执行回执，展示规划中、技能完成、失败或未验证；原始调用记录与评分不改写。只有独立原生反馈确认成功，才显示绿色完成标记；模型自己说成功不会产生这个标记。

2026-11-01 的“右手抓着瓶子直接放进篮子里”有两次 `place`，原生记录分别为 `20261101-234433-tamp-b2714a`、`20261101-234524-tamp-f59a05`。两次均 `placement_unreachable`、`primitive_success=false`、`native_commands=0`：本次搜索没有找到同时满足当前持瓶关系与目标姿态的方案，没有发出新的移动或松爪指令。这不等于已证明目标在所有规划方法下不可达。旧界面把调用返回画成绿勾，现在会显示失败原因和执行耗时，旧记录也能正确展示。检查材料集中在 `.runtime/ui-preview/place/`。
