# 瓶身抓取 v4

当前独立ASPIRE技能保持原程序和14个工具签名，更新了工具的抓取区域判断与带载放置规划。原固定TAMP演示和主页面框架不变。

## 本轮修改

- 右手每个有效接触点都必须在瓶身自底向上50%以内。旧60%上限会放行58%的高抓；新规则会触发已有的支撑确认、释放、实际退回和重新抓取，最多三次。
- 放置IK失败时，规划器保留目标瓶体中心和直立轴，尝试绕瓶轴±5、±10、±20、±30度的朝向，并重新检查IK、碰撞与路径。两例放置反例用5度替代完成，位置、释放、支撑、稳定和左手下沉5mm门槛均未放宽。
- 真机客户端要求包含不确定度的实测区域区间，支撑未知不松手，终止状态不继续；HTTP超时后保留已尝试的运动请求和未知结果，不再误报零运动。

## 实验

本地共159次原生技能实验，另有1次默认CLI整任务验收；381项平台回归通过，289054个原生转移已检查状态/时钟连续性。实验使用同一已登记直立瓶型，改变位置、轴向朝向、篮位±23mm、质量/摩擦×0.8至1.2，以及一次命令丢失或合成感知高度偏差。

原第一轮失败2207/2215明确转为第二轮开发反例，不能把修复后的历史回归称作新的留出成功。两组独立留出对照均打平，因此本轮证明了反例修复和未观察到新组退步，尚未证明总体留出成功率提升。最终48条件最大左手静止下沉3.21mm，原5mm门槛保留。

本轮没有训练神经网络权重。开发阶段Haiku API调用1次、3620 tokens，用于失败诊断；动作分支程序与v3相同，改进主要来自确定性工具契约和参数化规划。分布为工程压力范围，不是实测真机分布；仿真使用几何真值和暂停规划时钟，不验证视觉泛化或实时控制。不同瓶型、持续定位误差、真机负载补偿与真实成功仍待验证。

## 使用与迁移

本地运行 `./run aspire recover`，故障恢复可用 `./run aspire recover --fault receiver_close_loss`。当前后端为 `harness/aspire/placement.py`，v3程序/清单/说明保留在 `skills/bottle_recovery/history/v3/`。

公司端仅更新纯真机包 `OpenArmRobot-20261024-v4.zip`，没有仿真平台、模型资产或MuJoCo依赖。API配置保持不变，175项原部署文件检查无变化。感知和运动服务尚未实现，当前仍返回blocked，未进行真实动作。部署说明见 `docs/真机部署.md`，首次试运行准备见 `deploy/试运行.md`。
