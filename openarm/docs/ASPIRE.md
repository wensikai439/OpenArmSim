# ASPIRE 抓瓶技能

本机采用 NVIDIA ASPIRE 的官方 `ProgramExecutor` 和 `ToolRegistry`，以 OpenArm 适配器连接当前仿真后端。上游版本固定为 `fa00f0ef2bc1d91d594b9aa502c22133c9f538f7`。这是 ASPIRE 在 OpenArm 的适配实验，不是官方 LIBERO-Pro 成绩复现。

## 任务与边界

任务固定为右手抓起直立黑瓶、右手交给左手、左手放入原来的篮子。原有 TAMP 演示保持可用。

本轮动作工具使用当前仿真几何，模型也能查看三路固定相机关键帧。图片用于理解场景和检查失败，不构成视觉定位验收。瓶子位置只在回合开始前设置；随后完全由执行器和原生接触运动。不调整质量、摩擦、控制增益、碰撞或成功条件，不连接真机，也不生成新的 ACT/π0.5 权重。

## 运行

```bash
cd /path/to/OpenArmSim/openarm
./run aspire test --x 0.50 --y -0.17
```

该命令使用入库的冻结程序建立独立仿真，记录放在新的 `runs/*-bottle-skill/`。它不重置主页面的回合，也不操作硬件。坐标以机器人世界坐标为准：+X 向前，+Y 向左；右侧瓶子的 Y 为负值。超出已测试范围的调用只是额外实验。

新建技能发现实验：

```bash
./run aspire train
```

只在需要更换实验 API 时执行下列命令，随后按提示输入密钥：

```bash
./run aspire configure --base-url https://zzq.si/v1 --model claude-haiku-5-5
```

密钥保存在单独的系统密钥环记录中，不进入仓库、命令行参数、API 请求日志或实验文件，也不覆盖主页面原有 API 配置。

## 实验流程

1. 外部 Haiku API 看一组初始场景，通过结构化提交生成 Python 程序；官方执行器只注入允许的工具。
2. 在 5 个开发位置执行完整任务，向模型反馈失败阶段、工具回执和相关相机关键帧。每版都测全组，最多 6 版。
3. 根据开发结果选定程序并记录 SHA256，然后冻结。5 个独立检查位置和 20 个最终测试位置的结果不用于修改程序。
4. 在相同最终测试位置执行直接调用现有 TAMP 的基线，判断效果是否超出底层规划器自身的泛化。
5. 模型只从开发证据凝练方法。用独立 API 上下文、只给技能说明而不给获胜程序，最多两次重写复验；至少 4/5 通过才允许入库。

官方基准使用其他机器人、感知服务和更大的种子集合。本轮替换了机器人适配层、工具接口和位置生成器，使用暂停时钟的仿真执行，并缩减了测试规模。运行摘要必须保留这些区别。

## 如何判断泛化

程序不能读取种子、环境内部状态、文件或最终任务评分。动作中不允许重置或挪动物体；抓取和放置目标应来自当前工具观测，而不是记住的世界坐标。

任务成功必须具有右手抓取、右交左、左手入篮的原生成功回执，且最终有篮底支撑、释放和稳定证据。程序正常结束或模型声称成功都不算。

开发位置取 X=[0.468,0.538] m、Y=[-0.213,-0.133] m 内的确定性随机布局。用户指出固定程序与参数化工具不能混称后，又预先声明了覆盖 X=[0.41,0.59] m、Y=[-0.29,-0.09] m 的16点扩展检查；不能把这些范围测试说成任意位置、任意瓶子或真机泛化。此前8点边界方案在执行前被这组更大范围检查替代，声明仍保留。

扩展检查区分三种方法：冻结标称成功任务的关节指令、直接调用已有参数化几何工具、Haiku生成的程序。固定指令必须先在标称位置复现完整成功且关节状态吻合，才能用于新位置对照。新的16点每次任务最多60秒墙钟，超时计失败，不能挑选可达点后重算成功率。

若基线同样成功，位置泛化主要属于已有参数化 TAMP。新程序的观察、状态检查和错误中止是工程成果，但不能据此声称凝练带来成功率提升。独立复写通过只证明技能说明能传达程序方法，跨位置泛化仍须看冻结测试。

## 文件与复现

- `harness/aspire/`：官方执行器适配、受限 API 客户端、实验调度和检查。
- `skills/bottle_relay/`：通过复验后保存的程序、技能说明及证据清单。
- `runs/20261023-aspire/`：本轮完整试验；`protocol.json`、`frozen.json`、API 用量、所有失败和逐阶段记录均保留。

当前官方依赖只读复用 `/home/wsk/ASPIRE/libero-pro/source`。换机器时先准备同一提交的官方仓库，也可以通过 `OPENARM_ASPIRE_SOURCE` 指定路径；不修改上游仓库。

独立检查：`.venv/bin/python -B -m unittest harness.aspire.runtime_checks`。完整平台检查仍为 `./run check`。

参考：[官方仓库](https://github.com/NVlabs/ASPIRE)、[迭代调试流程](https://github.com/NVlabs/ASPIRE/blob/main/.claude/skills/iterative-debugging/SKILL.md)、[论文](https://arxiv.org/html/2607.00272)。
