# 瓶身抓取与稳定交接 v3

目标：从空手开始，右手抓住当前直立瓶子的下半瓶身，左手接上部瓶身，再放入篮子。两只手都不得以瓶颈或瓶盖作为抓取区域。机器人、物体和篮子必须属于已登记的候选仿真场景；几何输入来自仿真真值。

程序由 ASPIRE ProgramExecutor 执行，工具接口见项目 `harness/aspire/recovery_campaign.py` 中的 `API`。使用同目录 `program.py`，先核对 `manifest.json` 的验收状态和程序哈希。旧 `bottle_relay` 和固定 TAMP 演示保留。

## 可重建的策略

观测和工具结果都是只读映射；列表会成为元组，比较持瓶手时先用 `list(held_by)`。先确认空手、无接触、没有活动操作，且不是 terminal/invalid。本技能不接受任意中断状态作为新的入口；下述恢复发生在同一次执行内部。

1. `propose_grasps()` 根据当前瓶子几何给出经过 IK、路径和接近边检查的候选。动态取候选 ID，调用 `pregrasp(id)`、`approach(id)`，逐次检查 `ok` 和 `done`；不能写死坐标或 ID。`pregrasp` 保存实测的空手 TCP 检查点。
2. `close_gripper('right')` 后必须 `verify_hold('right')`，重新观测右手独立持瓶；闭爪指令本身不是抓取证据。
3. 仅在 `grasp_not_confirmed` 且双手都未持瓶时恢复：若实测右夹爪电机仍距张开端点小于 0.12 rad，允许一次原位补闭爪。若夹爪已闭却抓空，则 `open_gripper('right')`，通过 `retreat(checkpoint_id)` 实际运动回上次验证的空手接近位置；重新观测、排除刚失败的候选、重新提议和接近。排除只在同一 pose_revision 生效。最多三次抓取尝试；未知错误立即停止。
4. 右手真实持瓶后 `lift()`，工具要求实际抬升至少 6 cm，并通过 2 秒夹持稳定检查。重新确认右手独立持瓶。
5. `start_transfer(placement_aware=True)` 只启动操作，成功时 `done=False`。最多调用 16 次 `advance()`，每次只执行一个原生阶段。正常完成后已包含右手松开和撤离，不再调用 `finish_transfer`。
6. 如果交接返回 `dual_hold_not_confirmed` 或 `receiver_hold_not_confirmed`，先重新观测：仅在非 terminal/invalid、右手仍持瓶且有右手接触时，允许在当前已对齐位置 `close_gripper('left')`；分别验证左右手均真实持瓶，观测包含两手，再调用 `finish_transfer()` 受检松右手并撤离。不能带瓶回空手检查点，也不能从接收手贴近瓶子的状态盲目重启整个交接。
7. 重新确认左手独立持瓶。`start_place()` 也只检查 `ok`，随后最多 16 次 `advance()` 直到完成。最后确认双手均已释放。完整成功由原生物理验收判断，不能由程序文字声明。

所有同步动作都检查 `ok/done`。`last_failure` 是历史记录，恢复成功不会删除；判断下一步要看新观测。真实碰撞、失稳、超时、预算耗尽、未知 IK/接触错误均停止。最多 64 次适配器调用（含内部阶段推进）、120 秒原生仿真时间，不追加预算。

## 学到了什么

这是以开发失败、在线模型尝试和人工提供的专家纠正轨迹凝练出来的反馈程序。几何候选、碰撞检查、夹持判定和受检撤离由工程工具提供；模型生成如何根据这些反馈组合动作。没有训练神经网络权重，也没有证明模型优于固定规则。开发时模型曾混淆元组/列表、重启交接、把异步启动当成完成；被拒绝的稿件保留在实验记录。

恢复会实际退回一个语义检查点，不回滚物理世界。诊断故障只包括一次闭爪命令丢失或一次感知高度偏差；偏差在首次失败后撤除，是合成测试条件，不能冒充真实视觉重定位。只覆盖同一已登记直立瓶子和本次采样位置；倒瓶、双手都失去瓶子、任意物体、任意位置不在已验证范围内。

## 运行与部署

验收后执行 `./run aspire recover --fault stale_grasp`；不注入故障时用 `./run aspire recover`。这是独立的隔离仿真实验，不改变主页面正在运行的世界，不访问真机，也不需要 API。API 用于开发阶段生成/修订技能，冻结程序执行时按实时工具反馈分支。

v1结果在 `runs/20261024-recovery/`，详细结果以 `manifest.json` 和报告为准。规划及 API 等待期间仿真暂停，尚未验证连续实时时序。真机需要用真实感知、编码器/接触证据、轨迹控制和安全停机接口替换适配器，并重新验证标定与恢复边界；不能发送本仿真关节数组。部署说明见项目 `docs/真机部署.md`。

## 执行精度更新

分支程序与v1完全相同，更新的是工具实现：放置时按瓶体位姿生成最多4cm/0.18rad的小段目标，每段同时刷新目标计算和碰撞预测所用的手—瓶关系。中间TCP门槛6mm比原运输段12mm更严格，最后下降仍使用原3mm请求，最终释放、稳定和碰撞验收不变。恢复交接复用现代流程的受检空手归位。

最终另取6个新瓶位，各测试标称与组合压力，共12条件、24次成对原生试验：原工具6/12，新工具12/12，修复6例、无成对退步。组合压力改变篮位、轴向朝向、质量/摩擦及一次命令/感知故障。早先密集航点候选压力2/8、出现4例退步，未采用，记录保留在上级实验目录。这些工程范围不是实测真机分布，12/12也不保证连续域、任意物体或真机成功。

本轮没有追加模型API或训练权重。v1说明的独立上下文重建曾通过3/3，本轮没有重跑该项；分支程序哈希及13个工具签名保持相同。完整统计和源码冻结见 `runs/20261024-precision/final/`，退步候选及定位见 `runs/20261024-precision/diagnosis.md`。

接入包提供 `./run real preflight`、`./run real replay` 和 `./run real demo`。实测三维位姿/夹持服务未接入；`real shadow`只生成下一阶段提案并在执行前停止，不伪造执行后的持瓶状态。没有真机执行入口，本轮没有连接或修改真机电脑。详细步骤见 `docs/真机部署.md`。


## 瓶身约束与接收负载

本版增加第14个工具 `release_on_support()`：仅在原生接触证实瓶子静止支撑于桌面、左手未持瓶时，允许右手松开一次抓错部位的瓶子。若 `close_gripper(right)` 返回 `grasp_region_mismatch`，先通过该工具松开，再实际退回、重新提议下半瓶身候选；不能直接抬升，也不能在悬空时释放。其余13个工具签名保持。

右手候选采样为最大半径圆柱瓶身自底向上30%、40%、45%的区域；接收手候选为上部瓶身，瓶盖和瓶颈不作为失败回退选项。验收额外核对实际有力接触的几何和高度，不能仅凭规划目标判断抓对部位。

左手独立接收时，使用当前候选模型的负载质量、手部Jacobian和关节增益计算有限的关节参考前馈。它不改质量、摩擦、增益或物理状态；到关节参考限位采用显式抗饱和，并保留原位置跟踪、碰撞和夹持检查。交接后静止持瓶阶段的末端最大下沉超过5mm也判失败，即使瓶子最后入篮。

这些是本次工程修复，未调用额外LLM训练或修改模型权重。v1的3/3文字重建结果不作为v3复验结果；v2程序和清单保留在 `history/v2/`。新一轮覆盖与留出证据见 `runs/20261024-body/`。该控制使用仿真候选质量与增益，不等于已验证的真机负载补偿。
