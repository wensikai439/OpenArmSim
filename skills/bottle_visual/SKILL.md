# 视觉闭环抓瓶

实验入口，只验证右手抓住下半瓶身并抬起。它与旧 TAMP 演示分开，不复用 pick、handover、place、固定关节轨迹或物体三维真值。

## 当前结构

| 组件 | 形式与职责 |
| --- | --- |
| Haiku | API 根据接口、两张初始图和开发失败反馈修订 Python 程序；不是训练神经网络，也不是每个控制周期请求 LLM。 |
| ASPIRE | 使用官方 ProgramExecutor 和 ToolRegistry，程序只能调用七个公开工具；保留请求、输出和工具记录。 |
| 图像控制 | 从两路 RGB 检出瓶身目标与工具标记；通过小幅探测估计图像雅可比，移动后重看、更新雅可比。 |
| 机器人控制 | 编码器反馈、独立 IK、速度受限的关节插值和有界积分；两只手持续保持各自指令。 |
| 独立评分 | 原生物理接触、瓶身接触高度、实际抬升与持续持瓶；评分真值不提供给程序。 |

## 程序如何执行

1. 从当前 RGB 选择下半瓶身目标，开爪并设置接近朝向。
2. 先到侧前方，再用 6 mm 上限的图像纠偏接近。目标像素随每次初始化的瓶位改变。
3. 闭爪后检查编码器；第一次闭爪指令丢失时最多重试一次。
4. 实际抬升 75 mm，重新检查 RGB 中瓶子是否同步抬起；无证据就报错。

`visual_align` 是接收任意两视图目标像素的局部控制器，没有内置抓瓶、交接或放置流程。相对位置、倾角、步长和前置距离仍是人工指定的工程先验。

## 复现

在项目根目录运行，输出目录必须是 `runs/` 下尚不存在的新目录：

```bash
./run visual --case runs/20261025-visual/validation/position-1.json \
  --output runs/visual-check
```

完整冻结测试：

```bash
.venv/bin/python -B tools/visual_benchmark.py \
  --protocol skills/bottle_visual/evaluation.json --output runs/visual-suite
```

运行已经保存的程序无需再次调用 API。原始程序提交和用量记录位于 `runs/20261025-visual/model/`；密钥留在系统凭据库。

## 验证范围

`evaluation.json` 在留出测试前固定程序、控制器、测试位置与扰动条件。开发失败单独归档；失败初始化、失去跟踪、IK 或物理检查失败均计为失败。

通过必须同时满足：程序完成、原生双指抬起夹持持续至少 20 个控制周期、最终每个接触点均位于下半瓶身、RGB 抬升核验通过、原生物理状态有效。

## 尚未解决

- 只适用于本实验的已知直立黑色圆柱瓶；接近期间目标和两路相机保持静止。不是任意物体、任意位置或移动目标抓取。
- 两路固定合成 RGB 与虚拟平面工具标记是显式条件；真机需要可见工具特征、标记到 TCP 的几何关系，以及鱼眼畸变处理。没有验证现有真机相机能直接替代它们。
- 底层仍依赖机器人运动学；原生失效检测不等于预测式通用避障。IK 或跟踪失败会停止，没有物理重抓、避障搜索或跨障碍恢复。
- 没有调用旧 TAMP 补齐交接与入篮。新方法的左手交接、入篮和真机验证仍未完成；旧默认界面仍保留原有演示入口。
