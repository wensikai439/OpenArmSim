# OpenArm Harness

AI 调度、相对目标抓瓶 skill 和真实设备适配。r9 在 r8（连续粗接近与末段视觉纠偏）基础上加入通用标定向导、一键运行、cuRobo 全局规划，以及按当前场景在线搜索抓取/交接/放置位姿；不包含仿真平台、网页、模型权重或训练数据。

```text
LLMHarness/
├── run          命令入口
├── README.md
├── AGENTS.md    文件与设备权限范围
├── app/         agent、工具、感知、规划、控制、官方执行器
├── config/      机器人引用、标定、碰撞几何
└── records/     操作日志、验收记录、旧版本
```

环境在 `.venv/`，复用原 Python 3.10 机器人环境中的 OpenCV、RealSense、CAN、SciPy；FCL 仅安装在本目录。API 配置仍在 `.private/api.json`，不需重复填写。所有缓存留在 `.runtime/`。

## 现场只需要记两条

```sh
./run calib          # 标定进度和下一步：markers → measure → handeye → grip → accept
./run grab           # 一键抓瓶（也可 ./run 抓瓶）：预检 → 现场确认 → 启动设备 → Haiku 执行 → 关闭
```

本机（wsk）上可以直接敲 `oa calib`、`oa grab`，等价于 ssh 过来再运行。逐步说明、键位与安全事项见 [试运行](app/试运行.md)。

首次现场准备版本，尚未通过真机验收。合成完整规划仍有失败；搜索到预算上限会退出，不能把入口已安装当成能完成抓瓶。标定初始化也必须保留实测桌面避碰。

r9 起 ACT 参考源码指向 `openarm_deploy_bk_20261026`：原 `openarm_deploy` 于 2026-10-26 被替换，带日期的这份保留了绑定的 7 个文件，哈希全部一致。

## 常用入口

```sh
./run prepare deps   # 检查模块导入，不打开设备
./run check          # 无设备回归和故障注入
./run verify         # 校验代码与冻结 skill
./run relative       # 查看相对目标版本、接入方式与缺项，不打开设备
./run preflight      # 检查实测配置及验收证据
./run service        # 默认仅启动无设备服务
./run chat "检查准备情况，不要运动"
```

`./run prepare capture --confirm-on-site --camera right --seconds 10` 是未来现场使用的原始采集入口：打开指定 RGB-D 相机和延迟使能的 CAN 反馈，记录画面、深度、关节及原始时钟，**不使能电机、不初始化、不发运动**。它不会自动生成合格标定。

## 执行链路

- **Agent / ASPIRE**：保留同一 API，`run_bottle_skill` 已指向新版相对目标程序；官方执行器注入 16 个工具。Agent 读取结构化实测状态，不直接看原始相机图像。
- **感知与夹持**：注册标记 RGB-D 位姿、曝光时间映射、对应时刻 FK；结合物体在夹爪内位置、力矩及累计滑移判断持瓶。没有假设现场已经贴标记。
- **相对目标**：右手目标 = 当前瓶子位姿 × 实测抓姿；远处连续接近，最后约 18 mm（含 2 mm 容差带）才逐次观测、每步最多 6 mm。交接点依赖本次已核验 ACT 姿态的双手中点，放置点随当前篮子位姿计算。
- **规划与控制**：每一步重新检查完整双臂携物路径，再作原真机保守限速插值；双臂后台保持，接收夹稳后才松右手，确认右手撤离后才放置。
- **恢复与停止**：抓空可在支撑确认后释放、撤回实际预抓姿态并换候选；接收失败先保留右手。定位丢失、慢滑、未知回执和超时停止后续指令。
- **记录**：逐次 API、工具、CAN 请求/回执、双臂反馈、夹持证据及停止原因写入哈希事件链；设备会话另存关键 RGB-D 帧及曝光映射。

r8 保留速度 0.1 rad/s、加速度 0.2 rad/s²，增加参考 jerk 上限 2 rad/s³；这些是软件参考轨迹约束，不代表实测机械臂峰值。夹稳后停止推进闭爪目标并持续保持，接触力矩超过已验收区间上限即终止推进。没有提高控制增益。

每轮任务检查实际关节与待执行目标是否仍符合 ACT 初始姿态；偏离则拒绝新任务，不自动回位。异常终报保留原始错误、最后有效观测与清理失败，历史观测不会被当成当前成功证据。携物关系使用曝光对齐的 TCP。

规划器当前是有碰撞检查的局部 IK 路径搜索，不等于完整全局 TAMP；搜索失败会拒绝执行。原 URDF 的 0.3 mm 占位碰撞球不作为安全依据，碰撞配置改为原网格引用与外包多面体，仍需检查实际安装和夹爪全行程覆盖。

## 现场启动条件

软件已包含工具实现；真机是否可执行以 `preflight` 为准。相机外参、时间映射、瓶篮尺寸、夹持阈值、相对抓姿和完整夹爪几何未知时保持空值，不得把仿真结果填作实测结果。

`config/calibration.json → motion.relative` 集中放相对纠偏参数。`handover_offset_m` 是本次初始双手中点到安全交接点的实测偏移，`donor_retreat_base_m` 是右手交接后的实测撤离向量；两项未测量时保持 `null`，不能用仿真常量替代。

这是同一策略的**真机适配版**，不是仿真控制器原封不动迁移：当前感知使用真实 RGB-D 注册标记与 FK，不包含合成两视角、虚拟标记或自动探测相机的运动。单腕相机的全流程可见性尚未验证，不能将遮挡当成空手；当前没有多相机融合实现。旧程序留在 `app/skill/legacy.py` 作协议回归，旧发行保存在 `records/versions/`，不会自动回退执行。

完成现场分段测量后，验收记录应包含 `schema=openarm-physical-check/1`、类别、实测结果、操作员、有效期和配置/代码摘要。`./run prepare digest` 输出待验收摘要与缺项；代码、标定或几何变动会使旧验收失效。

只有现场操作员在场且预检全部通过，才使用：

```sh
./run service --devices --confirm-on-site
# 另一终端；首次应先完成分段验收
./run chat "右手抓瓶子下半身，交给左手，放进篮子" --execute
```

设备服务会先获取实测场景，检查完整初始化路径，再复用 ACT 的第 71 条初始目标与原插值程序，并核对实际到位。一次 skill 独占机器人；客户端超时会请求停止，服务也有会话租约和独立进度检查。主机软件停止不能代替已实测的电机/硬件看门狗。

当前发行未经实际相机/CAN/电机运行验收；离线测试通过、API 连接和程序返回均不能代替真机抓取成功。逐项步骤见 [试运行](app/试运行.md)。
