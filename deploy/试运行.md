# 首次真机试运行

本轮仅在本地仿真改进和测试技能，公司电脑不安装仿真，不启动真实动作。仿真参数扰动是工程范围，不是实测真机分布，也不能保证首次成功。

## 先补齐会决定成败的接口

1. 测量同一瓶子和篮子的尺寸、质量、初始位姿；确认机器人基座、桌面、TCP、相机内外参和时间同步。初次使用固定标称摆放，不从范围边缘或未知瓶型开始。
2. 接通新鲜的瓶篮位姿、夹持和抓取部位证据；区域置信区间必须落在下半瓶身，未知时停机。用已记录真机画面/状态核对接口字段后，再允许动作。
3. 用实测确认关节顺序、动作单位、夹爪命令与编码器反馈映射、轨迹控制语义及保持行为。不能把仿真TAMP允许的夹爪范围、关节前馈补偿或位置PD直接照搬到真机。
4. 在实时控制服务中实现14个工具、错误码、支撑释放和接收手验证；规划或API等待时，控制器仍要可靠保持。未知执行结果、过期观测和看门狗超时都停止，不盲目重发。

## 首次动作分段核对

操作员在场、停止手段可用时，先验证空手预抓路径；再单独验证右手下半瓶身抓取和持稳；随后验证左手接近、双手可靠持瓶与右手释放；最后核对左手独立持瓶是否下沉以及篮内支撑、释放和稳定。分段均通过后再运行整段任务。

技能的语义检查点是受检的物理姿态，不是把物理世界回滚到上一帧。没有桌面支撑时不能用“松开重抓”恢复；没有接收手证据时不能松供物手。

公司端 `./run status` 目前仍会报告真实服务未接通。上述接口和实测验证完成之前，不应把“API连通、仿真成功或技能文件已上传”描述为真机可执行。


## 本次准备结果

只读核对了当前ACT/DP/π0.5的公共启动目标：同一16维顺序、episode71、400步插值（10ms间隔）和5秒最终目标保持。新适配层复用该函数，按源码哈希固定版本，不导入原策略启动模块，不改原文件。现场仍需检查实际关节误差，并按基座/桌面坐标核对路径；同一姿态不能证明路径安全。

相对位姿的计算是T_base_tool=T_base_object×T_object_tool。已有技能按当前瓶体和手—瓶关系重算目标，不是把一条绝对轨迹平移。相对关系可以跨摆放位置复用，但仍需相机外参、TCP、时间戳和夹持几何。ACT的16维关节输出或use_relative_actions标志不能替代三维定位。

真实定位先准备了可选标记RGB-D基线，没有假定现场已贴标记；如采用它，应实际量取标记尺寸及marker_to_object，完成独立位置检查。也可替换为无标记检测/分割加位姿估计，输出相同的实测契约。现有VR校准文件只对齐手柄与手腕，不可填进相机外参。

日志应覆盖：源码/配置/skill哈希、初始化目标与实际误差、原始CAN位置/速度/力矩及接收时间、相机曝光/设备时钟/到达时间、3D位姿和不确定度、夹持/区域证据、完整双臂目标与反馈、每个API工具的请求及回执、停止原因、录像帧号及时间映射。包已实现文本事件链和驱动记录钩子，实际录像与硬件数据须在获准采集后验证，当前没有伪造真机记录。

当前预检会明确列出：camera_extrinsics、object_geometry、gripper_contact、timing、motion_planner、watchdog的物理验收缺失。服务仅以disabled模式运行，不能把监听端口称为真实运动已经接通。不要为消除blocked而把验收字段手填为true。
