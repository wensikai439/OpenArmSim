## 打开页面

使用临时公网地址 <https://excellence-nylon-falls-seeks.trycloudflare.com/>，网页使用 HTTPS 并经 Cloudflare 转发，无需 SSH。临时通道重启后地址会变化；长期固定地址需要正式域名或管理员提供入口。临时通道没有可用性保证。

项目管理员可在服务器目录运行 `.venv/bin/python -B deploy/server/tunnel.py status` 查看当前地址，或使用 `start` / `stop` 管理本项目的通道。该通道不写系统服务，服务器重启后需要重新启动。

原本机 SSH 隧道 `ssh -NT -p 32779 -L 127.0.0.1:8768:127.0.0.1:8767 root@10.255.1.213` 仍可用于管理排障。

## 登录与个人配置

登录使用已配置的共享访问密码。同一浏览器用持久 Cookie 记住登录，期限一年，每次访问续期；服务重启后仍有效。主动退出后需再次输入访问密码，但个人配置仍按原浏览器识别。清除 Cookie 或换浏览器会产生新的使用者标识。

首次进入填写姓名或昵称、个人实验目录名、请求地址、模型名称和自己的 Key，勾选确认后保存。默认请求地址来自[零词元接入文档](https://zzq.si/docs/quickstart)：`https://zzq.si/v1`，每位使用者可单独修改。Key 从[密钥页面](https://zzq.si/keys)获取，模型必须属于该 Key 可用范围，并支持所需的工具调用与图像输入。

每个浏览器的配置单独保存在 `.private/profiles/`，目录权限 700、文件权限 600。网页和公开状态不返回 Key。首次确认前不会发送模型请求；保存本身不调用模型，只有明确测试或发送任务才会调用。任务续跑与自动复查绑定任务发起者的配置和实验目录。实验记录、对话日志和工作区保存到 `runs/users/目录名-浏览器标识/`；此前根目录内的历史记录保留原位。仿真场景和执行工作台由使用者共享，同一时刻执行一项任务。清除 Cookie、换浏览器或换网址会创建新的浏览器身份和目录，原数据不删除。

## 管理服务

在服务器项目目录执行：

```bash
cd /data_ssdb/wsk/OpenArmSim
.venv/bin/python -B deploy/server/manage.py status
.venv/bin/python -B deploy/server/manage.py start
.venv/bin/python -B deploy/server/manage.py stop
```

管理器核对 PID、启动时间、命令和工作目录后才停止本目录进程；遇到端口占用直接拒绝启动。不要使用原来的 `./run keep`，它会写用户级 systemd 配置。当前进程独立于 SSH 会话，未修改宿主机的开机启动配置。

## 目录与资源

- `.venv/`：仿真环境。
- `.runtime/`：独立 Python、GPU 环境、渲染库、日志和必要运行缓存。
- `.private/`：登录密码哈希、会话签名密钥和各使用者 API 配置。
- `third_party/`：固定版本的 LeRobot 与 cuRobo 源码。
- `runs/`：实际产生的仿真记录。

当前使用物理 GPU 1（第二张 4090）；每次启动或长期运行前仍需检查共享机器占用。BLAS、OpenMP 与软件渲染线程设为 4，平台进程使用较低 CPU 调度优先级。相机由目录内 NVIDIA EGL 库在 GPU 上渲染，ACT 和 cuRobo 也使用同一张 GPU。NVIDIA 图形用户态库版本与宿主驱动同为 535.86.05，仅复制到本目录；未执行驱动安装器。未更改驱动、系统 Python 或其他人的环境。

测量程序 `resources.py` 只统计平台进程树；PSS 合计用于估算实际内存，CPU 的 100% 表示一个逻辑核心，服务器共 64 个逻辑核心。显存读数是 GPU 1 的整卡读数，共享环境下需结合部署前的 48 MiB 基线解释。当前目录总磁盘占用约 9.0 GiB，安装下载缓存与临时传输包已清理。数值是本次短程软件检查的实测，不是所有任务的资源上限。

检查记录位于 `.runtime/`：`resources-egl-idle.json`、`resources-egl-active.json`、`smoke.json`、`profile-check.json`。ACT 检查只运行合成输入推理，不执行预测动作；cuRobo 检查为原生仿真的短程移动，不代表完整操作任务或真机验证。

64 逻辑核心下，1.17 个核心相当于整机 CPU 的约 1.8%。显存已扣除部署前 48 MiB 的整卡基线。单次 ACT 合成输入推理为 0.650 秒，输出 32×16 且全部有限；没有执行这些策略动作。原生 cuRobo 规划的右手上移 3 cm 在 24.12 秒完成，包含规划器冷初始化，状态为 `primitive_completed`。1280×960 头部图像热渲染平均 3.42 ms/帧。

初版软件渲染的检查脚本在 120 秒超时，原生移动随后完成，原记录保存在 `smoke-first.json`；没有把脚本超时改写为成功。当前结果来自启用 GPU 渲染后的复测。以上不代表完整抓放任务、LLM 成功率或真机能力；付费 API 调用需由每位使用者先确认自己的配置。
