# 抓下半瓶身、交接并入篮

这是冻结程序的真机接入副本，不是神经网络权重或固定关节轨迹。由NVIDIA ASPIRE执行器注入14个具名工具；本副本不包含仿真工具实现，也未取得真机验收。v4保持程序和14个工具签名不变，将右手区域契约收紧为真实下半部：每个有效接触点（仿真）或含不确定度的实测区域区间（真机）都不得超过瓶身自底向上的50%。

1. 从新鲜实测观测确认空手、没有未完成动作、状态非终止且有效。
2. 依据当前瓶子位姿提议下半瓶身抓姿，先到预抓位置，再接近和闭爪；双指实测持瓶确认后才抬升。
3. 首次闭爪命令未执行可重试一次；抓空时张开、实际退回预抓检查点、排除失败候选并重新提议。最多三次，不回滚物理世界。
4. 若抓错部位，仅在真实支撑确认工具允许时释放，再实际撤离和重新抓取，不能在悬空时松开。

缺少实测区域区间时返回 `grasp_region_unverified` 并停止，不能用候选目标的40%高度证明实际夹持也在下半部。支撑未知时禁止自动释放。区域检查会改变对错误抓取的处理，不能因此放宽碰撞、持续夹持、抬升、稳定或入篮验收。
5. 开始右交左，逐阶段推进。接收失败且右手仍可靠持瓶时，重闭左手、分别核对双手夹持后才完成供物手释放与撤离。
6. 左手独立持瓶后开始放置，逐阶段检查反馈。碰撞、持瓶丢失、终止或无法解释的错误都停止。真实释放、入篮支撑和稳定应独立验收，程序返回不等于成功。

放置规划的迁移方法：若原目标的完整朝向使IK不可达，保持目标瓶体中心与直立轴不变，仅在绕瓶轴正负5、10、20、30度中搜索替代朝向；用最新手—瓶关系重算末端目标，检查原关节范围、碰撞路径、位置精度和稳定约束后再执行。该方法需要在真机运动服务中实现和验收，本包没有把MuJoCo规划器上传，也没有用仿真关节轨迹驱动真机。

该程序的动作泛化依赖真实工具每次按观测重新计算抓姿和路径，以及接触/夹持证据；把仿真坐标或轨迹复制到真机不具备这个条件。仿真负载补偿没有随此包迁移为真机控制代码，真机左臂带载稳定性需要独立验收。

真机工具服务缺失时，harness明确返回blocked。只有接通并验收真实服务后，才能在操作员在场时用显式 `--execute` 执行；当前部署未启动过真实动作。
