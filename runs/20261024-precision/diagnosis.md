# 失败定位

本轮全部在本地完成，没有 SSH、相机、CAN 或真机动作。没有追加模型 API 调用。skill 的分支代码保持相同，修改的是受检工具执行层。

| 证据 | 判断与修改 |
|---|---|
| 原1002在放置开始45个控制步后中断；末尾双指瞬时接触仍在，但连续夹持仅8ms，关节跟踪误差约0.08rad | 应称为夹持连续性中断，不能仅凭这一帧宣称瓶子已掉落。关节插值没有约束途中瓶体姿态，改为瓶体位姿分段运动 |
| 原1011恢复交接后瓶轴竖直余弦降至0.699，右手仍接触瓶子，后续碰撞规划拒绝 | 恢复分支调用旧撤离；改为现代交接已使用的受检空手归位，保留左手持瓶和右手脱离检查 |
| 仅放慢至0.35仍出现start_collision；保持完整夹爪姿态的轴向撤离也会IK不可达 | 降速不是充分修复；这些候选保留在development |
| 第一分段候选：新位置8/8，组合压力2/8；原工具分别4/8、4/8，出现4个退步 | 未采用。目标计算刷新了手—瓶关系，碰撞预测却继续用旧关系，存在内部不一致 |
| 抓持关系同步刷新、4cm/0.18rad航点后，1113因TCP误差4.47mm被新加的4mm中间门槛中止 | 中间航点取6mm，比原运输段12mm更严格；最终下降仍遵守原3mm请求，独立物理验收未变 |
| 最终五个开发反例全部通过，耗时约81–89仿真秒 | 缩小航点数量降低延迟；最终泛化另用final中的新随机条件，不能把已调试案例当留出数据 |

`sources/` 保留被替换候选的源码；根目录protocol/results是未采用候选的32次成对测试，`final/`是最终冻结实现的新条件。开发失败未删除。

范围仍是已登记直立瓶子、候选机器人/接触模型和仿真几何真值。绕轴旋转轴对称瓶子不能证明倒瓶或一般形状的姿态泛化；工程质量/摩擦/篮位扰动不是实测真机分布。规划时钟暂停，仿真毫米误差不能直接当作真机精度。
