# TAMP 目标与机械臂可达性扫描

日期：2026-10-13。复核“瓶子往前放”时，区分了两类失败：页面模型请求曾在动作前收到 HTTP 402；原生 TAMP 则能移动瓶子，但指定左手后在部分目标姿态下无法放置。

## 结果

- 24 组：3 个记录机器人初始关节姿态 × 左右手 × 前进 8 cm、左/右 4 cm、后退 4 cm。瓶子起始位姿、直立状态和桌面保持固定。使用 MuJoCo 真值几何，不调用 LLM/API、相机感知、GPU 策略或真机。
- 首次执行 18/24 放置成功；6 组都是左手抓起后，携瓶放置遇到 `placement_unreachable` 或 `ik_unreachable`。没有更改目标，也没有释放瓶子。
- 对这 6 组，在同一仿真状态和锁定目标下交接给右手，6/6 放置成功；落点误差 3.23–5.34 mm。没有重置、物体瞬移或放宽验收门槛。
- 因此该窄场景的最终结果为 24/24，前提是允许失败后换手；首次成功率仍单独记为 18/24。这不是物体、视觉、场景或真机泛化率。

## 复现

```sh
./.venv/bin/python -B tools/check_tamp_target_sweep.py
```

逐例结果、起始关节角、失败/恢复路由、误差与模型哈希见 [`result.json`](result.json)。编译模型标记 `physically_calibrated=false`、`transfer_ready=false`。入口 [`check_tamp_target_sweep.py`](../../tools/check_tamp_target_sweep.py) 不改默认技能或物理模型。

## 下一步

未指定机械臂的任务需要比较双臂可行路线；明确指定左手/右手时则必须保留该约束。当前 `relocate` 工具要求模型传入 `arm`，换手恢复也是可选参数，所以模型选到不可达手臂时可能失败。自动选臂/恢复应作为后续 TAMP 能力，分别测首次规划和恢复成本。页面 HTTP 402 仍阻断真实 LLM 闭环，本扫描没有绕过 API。
