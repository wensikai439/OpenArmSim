# Agent 阶段工具路由复核

日期：2026-10-13。此项按长期计划的 P0.4 处理，复核“前移放置失败”的模型/API 与工具路由证据。这里只跑 CPU 软件检查和文本 API 连通探测；没有真机、GPU、ACT、cuRobo 或 π0.5 动作。

## 结论

- 瓶子向机器人前方移动 8 cm 的原生 MuJoCo TAMP 技能链已在 [定向复测](../20261013-forward-tamp/README.md) 完成，单次落点误差 2.38 mm。它证明该固定已知场景可执行，不证明视觉模型或任意初态泛化。
- 2026-10-11 的页面调用记录显示，模型读取观测、检查操控状态并提交 `set_plan` 后，下一次 API 请求收到 HTTP 402；没有返回动作工具调用，TAMP 没有开始。2026-10-13 先后两次只发文本连通探测（各一次，无相机或机器人状态）：均返回 HTTP 402；最近一次 `max_tokens=16`。响应没有给出足够证据判断具体计费原因，没有重试任务。
- 同一旧任务档案还保留了 `place` 先于计划中的 `pick` 的调用；阶段守卫拒绝了放置，没有启动该动作。旧记录不能证明当时请求给模型的工具列表是否已过滤。
- 发现当前代码的本地回包白名单仍按全量技能表校验，和发送给模型的阶段过滤结果不同步。已修改 `harness/agent.py`：每次决策先生成本次可用工具集，发请求与校验单/批量回包共用该集合。返回未公开工具时明确记为未执行。

## 验收

- 新增 provider 边界测试：计划阶段只公开 `pick`；取得抓取回执后只公开 `place`。
- 新增完整对话模拟：模拟模型故意返回被隐藏的 `place`，验证请求白名单没有 `place`、本地回包被拒绝且 `motion_started=false`。
- 阶段、对话、任务目标、工作区等定向测试：66 项通过。
- `./run check`：205 项通过，包含真实 MuJoCo 前移抓放回归；这是软件/仿真契约检查，不是 LLM/API 成功率。
- 受管服务重启后报告 `ready`、`source_current=true`、`job=null`、tick 0；加载源码 SHA256：`ac78431f7432580cbff6bf55c3c1a933e8ddea770843ebb28ad337b883d2e2e7`。ACT 与 cuRobo worker 仍未连接。

## 剩余门槛

HTTP 402 修复前，不能验收真实 API→阶段工具→物理执行的端到端闭环。当前变更提高了隐藏工具回包的防护和失败解释，不会替服务商恢复 API 额度，也不自动改走脚本或其他提供器。工作台视觉点击验收仍未做；本轮浏览器策略拒绝本地页面访问。系统驱动认证未完成，故 P1 能力注册改造仍等 P0 门槛。
