# OpenArmSim验证矩阵

更新：2026-10-13。此表用于把接口/程序测试、原生仿真、GPU策略、历史档案和真实迁移分开报告。通过某一层不替代更高一层。

| 层 | 入口与依赖 | 会验证什么 | 不代表什么 |
|---|---|---|---|
| 源码静态检查 | `sh -n run`；对入口文件用Python `compile()` | 语法与启动脚本可解析；不需服务/API/GPU | 不验证物理行为 |
| 合同/单元回归 | `./run check`，由`sim/cli.py`装载`sim.*_checks`与`harness.*_checks` | 当前登记的机器人模型、技能、数据结构、控制/碰撞与记忆规则 | 当前轮尚未重跑；不含真实API、ACT/π0.5推理、真机或完整界面验收 |
| 本机HTTP服务 | `./run start`、`./run status`、`./run stop`及`/health`、`/api/status`、`/api/frame` | 8767生命周期、任务状态、相机帧、源码与策略worker就绪原因 | 服务ready不等于任务成功或ACT可用 |
| 仿真动作/回放 | `./run tamp ...`、`./run replay ...`或明确选定的页面技能 | 特定初态、命令/规划或记录轨迹下的原生MuJoCo结果 | 回放不等于感知控制；已知物体几何结果不等于视觉泛化 |
| GPU策略集成 | ACT本地policy服务、cuRobo worker 8004/8005、官方OpenPI适配链 | 权重、接口、依赖、CUDA及原生动作闭环 | worker启动/单次推理不等于整项任务通过；需要冻结场景与评分 |
| API/harness集成 | `tools/check_*_api.py`或页面真实模型API；需列出会调用的provider及费用 | 模型是否选工具、参数、执行回执、复查和恢复 | 假provider/协议测试不等于真实API；API成功不等于任务通过 |
| 历史实验审计 | `runs/`内manifest、日志、报告与其锁定源码 | 复核以前一次实验和数据链 | 缺少历史fixture时不能静默跳过，也不能将旧代码成绩移给新代码 |
| 配对sim→real | 新授权、独立实测校准、相同任务/模型/初态的真机试验 | 指定任务范围内的迁移差距 | 当前软件回归、相机相似或真机轨迹回放都不构成通过 |

## 执行记录规则

- 先记录代码/配置版本、测试命令、样本和初态；出错保留原结果，不重复运行直到变绿。
- API、GPU与真实硬件分别列明。没有请求、没有连接或权限缺失时记为“未运行/等待”，不计成功也不计任务失败。
- 带运动的MuJoCo脚本会改变本次仿真状态并可能写入`runs/`，与纯合同测试分开调用；真机脚本没有默认入口。
- 当前`handoff`压缩包的`tools/verify_handoff.py`只在包内，依赖随包的参考轨迹与帧；便携包验收须在干净解压目录完成，并记录包SHA256。
- 本地父项目Git只跟踪源码/小型配置与显式实验摘要；`runs/`历史大目录、`.runtime/`、`.venv/`、模型权重、状态数据库和缓存不进入版本库。`openarm_mujoco/`以独立上游子模块提交固定版本。

截至本次更新，已通过P0.2对应的服务启停、源码变更门和异常恢复验收，记录在`runs/20261013-runtime-lifecycle/README.md`。`./run check`及完整便携包重建/解压验收留待P0.3/P0.4；GPU worker因本机驱动未加载而没有通过。
