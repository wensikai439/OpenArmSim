通过左侧聊天发送任务会调用已保存的 API；「手动工具 · 跳过 API」直接启动工具。模型身份和启动来源写入运行 manifest，不能根据画面动了就认定调用过模型。旧版 `20261001-194433-tamp-90b16b` 已记录 `deepseek-flash` 发起完整 TAMP，原界面遗漏了调用过程显示。

- **过程卡片**：后端实时记录观测、记忆读取、每次 API 请求、工具名称／参数／返回、耗时、token 用量和失败。请求进行中即可看到状态；详细参数按需展开。仅显示公开动作记录，不保存或展示供应商的私有推理字段、密钥和图像 base64。模型回答支持安全的粗体、代码与列表，长回复可折叠。
- **模型阶段**：模型必须先调用 `set_plan`，自行决定 1–8 个阶段的名称和顺序，再启动 TAMP/VLA。没有计划时不会替模型填固定模板。各阶段绑定已定义的检查条件，系统根据同一 `execution_id` 的证据更新进度；模型不能写 `done`。`left_release_at_basket` 专指左手在篮中释放，与交接时右手打开分开。视觉复查可以显示「不确定」，不覆盖仿真评分；手动执行则显示原有物理检查。
- **记忆**：偏好和经验证的方法／失败教训在页面展示；调用日志与原始任务回执保存在 `harness/state/agent.sqlite3` 及实验目录，默认不注入长期索引。页面可增删偏好并清除当前职责的记忆。证据区分模型判断、工具约束与仿真特权来源；模型须显式请求才能读取特权回执。场景笔记绑定观测 epoch，重置后不再注入模型上下文；执行与研究职责隔离。重启保留历史，但不恢复旧动作或旧阶段的实时状态。

## 真实运行与记录

物理状态由服务端线程独占。页面刷新、切换标签或关闭页面不改变仿真步进，也不会重新启动实验。策略控制周期为 30 Hz，物理步长 1 ms，以 33/34/33 步交替执行。**真机指令回放与控制响应辨识使用原始记录的不等间隔时间**，每个指令保持到下一条记录；积分时间与记录时间偏差不超过 0.5 ms。N 条观测定义 N−1 个已知指令区间，最后一条指令没有后续时间戳，因此不臆造执行时长。闲置时仿真暂停。

`reference/acquisition.json` 保存前三条原始 `trajectory.json` 的相对记录时间、源文件哈希和全部 16 维状态/动作的逐帧对齐结果。三条实际记录时长为 31.417532 / 28.124958 / 32.074137 s，原先 `frame/30` 分别给出 28.933333 / 25.366667 / 29.666667 s。它们是 logger 的 `record()` 时间，不是相机曝光或 CAN 下发时间；零阶保持与零偏移仍是假设。缺失或不匹配的时间证据会报错，不静默退回 30 Hz。

每一步保存 `observation(t) → action(t) → observation(t+dt)`。16 维顺序为左臂 7 关节、左夹爪、右臂 7 关节、右夹爪；关节是绝对弧度。夹爪指令是目标电机角度，反馈是实测电机角度，**二者使用同一 rad 坐标**，不应分别归一化。当前到指关节的传动变换仍是候选：反馈极值不能标定真实开口。电机增益通过虚功关系换算到 v1 直线指关节，力上限为候选 333 N。环境拒绝非法动作；VLA 适配器先按真机部署代码对每侧 7 关节位移做 L2 限幅，再裁到关节范围，同时记录原始预测、实际下发值和限制原因。夹爪越界仍拒绝，尚未确认真机夹爪饱和规则。

每个 `runs/<时间>-<类型>-<编号>/` 包含：

- `manifest.json`：引擎、来源、代码/数据哈希、参数、种子、策略身份及记录模式。
- `transitions.jsonl`：控制周期的前后状态、动作、物理评估和诊断。
- `summary.json`：真实终止原因、指标与不确定性；进程结束不是任务成功。
- `events.jsonl`、`keyframes/`：阶段证据与可复查画面。
- 开启图像记录时，`images/{head,left,right}/` 保存每个观测时刻的 RGB PNG，初始观测和最后一个观测均保留。

仅关键帧的运行不标为 VLA 训练数据。`sim/dataset.py` 使用官方 LeRobot v3 写入器，并逐帧验证动作、状态和三路图像像素。原始物理时间以额外字段保留，LeRobot 索引时间为 frame/fps。失败/未完成的运行只能导出为 diagnostic。**不等间隔记录回放也只允许 diagnostic 导出**；索引时间不等于重采样，正式模仿训练需要另行完成经过验证的时间重采样。成功的等间隔策略数据仍需成功标签审核和独立验证集。历史 `tools/to_lerobot.py` 只面向旧版 episode，不用于新记录。

## 腕部相机候选

「实验详情」内的「拟合腕部相机」、研究工具 `fit_wrist_camera` 和 `./run wrist` 使用同一有预算的实验流程。研究工具 `inspect_wrist` 返回真实原图、当前模型、候选投影及轮廓叠加图；它只有历史证据 ID，不提供执行策略所需的新鲜观测 ID。执行角色不可调用。页面的原有三块布局保留。

固定协议 `wrist_silhouette_v2`：每侧只使用 ep0 第 0 帧拟合；ep1 第 0 帧及 ep2 第 100 帧做开发验证。先以 EE 局部夹指网格提出相机位姿／视场角候选，再以原生 MuJoCo 分割渲染优化，保留机器人遮挡及真实近裁剪设置。选择后先保存参数，再读取验证掩码。暗色区域的固定分割规则遇到瓶子与夹指相连时会明确排除；不根据候选效果修掩码。其余帧仅提供画面复查，不计分。

页面实际启动并完成的实验在 `runs/20261001-024101-wrist-34d68f/`，耗时约 9.8 秒。左腕两帧开发验证 IoU 平均从 0.059 提高到 0.809；右腕一帧从 0.080 提高到 0.783；ep1 右腕因瓶子遮挡导致分割歧义被排除。IoU 是原生模型可见夹指与图像掩码的交并比，不是任务成功率。`index.html` 可逐组查看、点击原尺寸图；`interface-check.json` 核验四张图内容、执行角色拒绝及实时观测未被改变。

**候选未应用，物理标定未通过。** 两侧视场角都接近 100° 搜索上界；单一开口下的相机焦距、距离和夹指几何存在耦合。整体桌面视角、夹指形状与闭合状态仍有差异。必须核验实际夹爪版本、开口映射及相机安装，用多开口和独立场景对应点验证，不能只凭轮廓 IoU 推广到 VLA 输入。头部相机不在本次拟合范围。

`tools/fit_wrist.py` 的几何／原生阶段用项目 MuJoCo 3.14；数值优化复用既有 OpenPI 环境的 SciPy/OpenCV，既不导入该环境的旧 MuJoCo，也不安装依赖。每次实验的源代码快照、输入网格、协议、参数、掩码、报告与日志都留在同一 `runs/` 子目录。运行参数和 SSH 源文件不变。

## Harness 和模型角色

视觉 LLM 看新鲜的头部/左右腕图像与本体状态，选择工具、检查结果、解释失败。文本 LLM 不接收图像，只能使用明确标记的 TAMP 场景信息基线。当前 ACT 已接入核验过身份的真机权重，但完整仿真任务未通过；π0.5 尚无匹配的 OpenArm 检查点，不把整段策略任意拆成未训练的子任务。全景仅供操作者调试；物体真值进入仿真评估和 TAMP 的独立基线，不混入 VLA 输入。三路图像都保留机器人本体遮挡。

`GET /api/tools?role=execute` 返回执行工具；`POST /api/tools` 接受 `{ "role": "execute", "name": "observe", "arguments": {} }`。省略 role 时默认 execute。

| 工具 | 用途 |
|---|---|
| `observe` | 同一时刻三路画面、本体状态、唯一观测 ID |
| `set_plan` | 模型提交本次任务的阶段标题和检查条件，不能自己标记完成 |
| `list_skills` | 读取能力边界、后端是否可用和兼容的已记录技能结果 |
| `recall_memory` / `remember_scene` | 按技能、任务和版本检索成功/失败经验／保存绑定当前观测的场景假设 |
| `pick` / `handover` / `place` | 当前声明瓶子：左右手抓取、双向交接、桌面定点或篮内放置；显式使用仿真场景信息 |
| `move_to_pose` / `move_relative` | 指定末端位姿或有限相对位移，重新求解 IK 与碰撞路径 |
| `run_policy` | 调用实际配置的 ACT/π0.5 原子策略；无检查点时明确报错 |
| `get_run_status` | VLA 仅返回进度；TAMP 额外返回明确标注的单步结果、失败原因，始终不返回整段任务评分 |
| `stop` | 停止实验；正在等待推理响应时受网络超时约束 |
| `finish` | 对已结束运行提交视觉判断；记录到日志，不改变独立评分，工具回包不泄漏评分答案 |

当前场景内，执行与实验聊天保留各自最近 6 轮文本上下文；持久记忆另行检索，职责不混用。TAMP 技能结束后，新观测与反馈触发同一目标的下一次决策，可继续、修改方案或结束。当前学习策略仍是从重置状态运行的完整原子任务，结束后只复查，不伪造未训练的子技能。`run_tamp` / `run_pi05_vla` 仅作为直接开发接口保留，不再声明给 LLM。页面保留独立物理评分和模型判断；跨重启记忆可读取，但不会自动恢复机器人动作。记忆物理兼容契约为 `openarm-memory/4`；规划服务代码变化不会清空物理条件一致的方法，迁移必须核对原生源码与反馈，删除标记保留。尚无经过统计评测的记忆收益或技能内部实时纠错。

页面可切换「实验与训练」；外部 agent 使用 `GET /api/tools?role=research` 和 POST 的 `role: research`。实验模式具有 `list_experiments`、`get_experiment`、`get_calibration`、`fit_controller`、`evaluate_timing`、`export_dataset`、`train_model`、`evaluate_model`、`get_job_status`、`stop_job`。它可以读取特权诊断但没有执行 VLA 的工具。这是受控聊天工具的数据边界；操作者的调试页面与本机文件权限不属于沙箱隔离。

学习任务复用 `sim/learning.json` 指定的官方 LeRobot 环境，启动时校验源码 revision 和 tracked 文件未改动；不往该环境安装包。任务不继承 LLM 密钥或 SSH agent。只允许固定 Python 模块与配方，不接受 shell；任务 ID 不能包含任意路径。一次只运行一个学习任务，启动与停止记录在 `runs/<job>/job.json`，进程日志在 `worker.log`，模型与评估在 `artifacts/`。服务重启后遇到旧 running 记录只报告 unknown，不自动重启或按旧 PID 杀进程。

- `act_smoke`：CPU、1–10 步、小网络，允许诊断数据，仅验证训练链路。
- `act_baseline`：CUDA、最多 10000 步、要求成功仿真示范；仍是候选模型，不自动晋级。尚未完成正式任务训练。
- 导出最多 30 分钟；smoke 最多 5 分钟；baseline 最多 2 小时；预测评估最多 15 分钟。取消只作用于本服务创建的进程组。
- `evaluate_model` 使用保存后的预处理、模型和反归一化链，在另一条 episode 上比较首步动作。拒绝同一来源 episode 的重复回放。关节误差和夹爪命令误差分开计算；**这不是闭环任务成功率，也不能据此批准真机迁移。**

当前已经通过官方导出、CPU ACT 训练、预处理器/检查点重载与另一条 episode 预测的实际工具调用验证。证据见 `runs/20260930-230959-evaluate-0e773d/verified_tools.json`；配套 `artifacts/learning.png` 展示真实 loss 与关节误差。检查点和归一化文件的内容哈希在评估前重新核验。测试数据仅 15 个训练控制步和另一 episode 的 12 个评估控制步，模型只优化 5 次，不能据此判断任务能力。

没有配置模型时，聊天明确显示未配置；模型出错时不会换成脚本继续计分。

VLA 使用官方 OpenPI MessagePack/WebSocket 数据协议。设置 `OPENARM_POLICY_CONFIG` 指向经过核对的本地 JSON；参考 `harness/policy.example.json`。必须填真实检查点身份、它训练时的输入键、RGB 布局和 OpenArm 16 维语义。只允许本地推理端口。LIBERO 的 7 维检查点不能直接当作 OpenArm 模型。示例里的输入键只是模板，不能假设适用于现有检查点。

另有官方 LeRobot π0.5 适配器 `sim/pi05_server.py`，用于远端已核查的 16 维绝对 Joint 检查点。它只接收本地仿真 RGB 与状态，不导入远端部署代码、摄像头或 CAN 驱动。原始 HWC uint8 图像无损传给官方预处理器；保持保存的 QUANTILES 统计、tokenizer、224×224 等比例填充、50 步动作块和 10 次推理迭代。双臂限幅仍在每个物理控制步以新反馈计算。

`./run policy-check` 只读核验本地模型及九个伴随文件的完整 SHA256；`./run policy-serve` 用既有、固定版本的官方 LeRobot 环境启动 loopback 推理服务。按模型导出授权范围读取副本，将其置于 `models/pi05/checkpoint` 并保留核验后的 `models/pi05/source.json`；远端只读。客户端配置参考 `harness/lerobot.example.json`，`checkpoint` 必须使用 `policy-check` 返回的组合内容摘要。启动仿真时设置 `OPENARM_POLICY_CONFIG`；不能用示例占位符执行。

适配器直接调用官方模型类与键名转换，再执行会抛出异常的严格权重加载，并逐项比较实际张量，避免上游加载函数捕获异常后返回未加载模型。服务与客户端核对模型身份、输入尺寸和动作语义；每轮独占会话，固定随机种子，按序收取观测，超时不自动重试推理。推理等待行为由下面的 timing_mode 显式声明。

## 成功判定与当前缺口

右手两指接触持续、瓶底离桌、双手同时接触、右手释放后左手持瓶，再到瓶子完整 XY 外形进入篮子、接触篮底、所有手指释放、低速稳定至少 1 秒。不能通过指定时间点、夹爪命令、瓶子中心入框或直接把瓶子放进篮子来伪造整段任务成功。运行中不会焊住瓶子、搬动物体或把机械臂关节强制写成参考轨迹。

接触按每个 1 ms 物理子步采样，控制周期末再做一次不增加计时的状态检查。两指夹持、稳定放置和深度穿入要求连续的物理采样支持；短暂失去接触会重置相应计时。10 mm 以上连续穿入达到 100 ms，或瓶子掉到工作台以下，会使实验无效。接触法向力通过 MuJoCo `mj_contactForce` 读取，不增加额外求解或更改运动状态。阈值是当前任务评估设置，并非实测的硬件安全阈值。

每个 transition 的 `evaluation.contact_window` 保存实际子步数、接触持续时间、峰值法向力、法向力时间积分，以及接触几何体/刚体名称。冲量是各接触点法向力的标量时间积分，不是真机测量，也不等于笛卡尔净冲量。完整任务中允许抓持等必要接触；仅无接触控制器辨识排除机器人接触。

必须补齐/核验的项目已列于 `sim/profile.json`，页面「标定待完成」可查看。关键的历史解释修正：

1. `epos` 来源于相同 URDF 的正运动学，零残差只能证明软件坐标约定一致，不证明物理基座、关节零位与 TCP 已经标定。
2. 0.15 m 安装高度是候选下界。现在编译为固定安装变换，不在回放中反复覆盖升降柱 qpos。
3. 0.2466 N·m 是日志观测峰值，不是已确认的夹爪力矩上限。历史 v2 的 7 N·m 与当前 v1 的 333 N 分别是转动/直线指关节的上游限制，均不是实测真机电机限矩。
4. 瓶位由闭合时刻和假设的指垫几何推得，不是独立位姿测量。56 mm 瓶径、质量与摩擦仍是候选值，不能按「哪次回放成功」来宣布标定完成。
5. 缺少三路完整内外参与畸变。2026-09-30 只读核查发现：两个远端部署副本的 `pyroki_/config/vr.yaml:34-35` 明确将旧 `calib/left.yaml`、`right.yaml` 用于 VR 控制器到腕部的标定；此前将其称为相机外参是误判，已在本地 `calibrate.json` 更正并保留原数值追溯。当前相机仍是上游模型，不称为真机等价输入。
6. 在相同指令 `u` 下，`(u-q_sim)-(u-q_real)=q_real-q_sim`，所以比较两种跟踪误差的平方与直接比较位置残差等价。不能用这个代数改写证明误差不可辨识。需要同时核对采样时序、延迟与控制器语义，并在未参与拟合的轨迹上验证。
7. 148 条记录的成功标签未独立核验。本地三个片段不足以证明全任务分布的仿真可信度。

2026-09-30 的首轮原生回放 ep0 在 767 个控制步后因瓶子掉落结束；`success=false`。这是一条失败诊断记录，不能记为复现成功或真机可迁移。后续修改必须重新运行并保留自己的配置哈希。
