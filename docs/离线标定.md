# 旧数据离线标定

2026-10-25 首轮结果：**完成离线试验，未获得可部署的相机标定**。运行参数和真机验收状态保持原样，没有启动相机、CAN 或电机。

## 数据与方法

- 公司电脑只读提取 4 段轨迹、3345 条状态/动作记录；两轮读取的 75 个源文件最终 SHA256 相同。
- 头部相机使用 26 张原始 JPEG、52 个人工腕部轴心近似点。相机像素坐标不经过裁剪或缩放。
- ep0/ep1 的 28 点拟合；ep2 的 12 点开发验证；新增 ep3 的 12 点跨轨迹验证。它们不是 3345 帧视觉评分。
- 固定采集 URDF 和关节角，比较普通透视与一阶鱼眼模型；只用拟合数据的 AIC 选择模型，先冻结参数再验证。
- 方法参考 [NVIDIA DREAM](https://github.com/NVlabs/DREAM) 的 2D/3D 对应思路与 [OpenCV 鱼眼模型](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)，未接入 DREAM 网络或训练权重。

## 结果

| 数据 | 点数 | RMSE / px | P95 / px |
|---|---:|---:|---:|
| 拟合 ep0/ep1 | 28 | 31.12 | 54.91 |
| 开发验证 ep2 | 12 | 43.94 | 91.25 |
| 新增轨迹 ep3 | 12 | 61.04 | 113.40 |

鱼眼模型优于透视模型，但跨轨迹与删除单帧敏感性检查未通过。16 px 是本轮探索筛选线，不是机器人实物容差。

这些误差属于“人工近似点＋候选 CAD/关节零位＋相机模型”的整体不一致，不能解释为真机或仿真的空间误差。CAD 粗复查预试仍未解决问题，冻结候选保持不变。

夹爪统计使用全部 3345 条记录，按持续稳定的开合指令分组。不同轨迹、不同阶段的实际反馈有差异；未用闭合指令冒充夹瓶成功标签，也未生成夹持力阈值。

## 第二轮与自检

瓶盖中心的自然特征方案使用 64 张原图，按每次夹持分别估计瓶盖到腕部的固定关系。相机仅用 ep0/ep1 的 32 点拟合；ep2/ep3 每段先用 3 帧登记局部点，剩余 5 帧验证。与轴心方案的特征和数据不同，不能直接声称改善百分比。

| 检查 | 结果 | 判断 |
|---|---|---|
| 瓶盖拟合 | RMSE 9.55 px | 主点触及搜索边界，未接纳 |
| 剩余帧验证 | 可评分 10/20 帧，RMSE 21.09 px | 两段左手登记失败，仍算失败 |
| 记录偏移扫描 | 拟合最优偏移 −4 条，RMSE 8.03 px | 最优值在边界，未识别真实延迟 |
| 偏移后的验证 | 可评分部分 RMSE 25.42 px | 比原方案更差，未采用 |

自检修复了验证点被拟合入口提前要求的问题，并拒绝退化、超出合理范围的相对点。失败片段保留在分母；完全不可评分时报告显示“不可评分”，不隐藏失败或生成虚假的绿色投影。

10 项检查覆盖独立 OpenCV 投影、已知相机参数恢复、已知腕部点三角化、源数据锁定、拟合/验证分离、退化登记、失败覆盖率与夹持证据边界。它们是软件检查，不是真机验收。

[瓶盖结果](../runs/20261025-offline/carry/result.json)、[时间诊断](../runs/20261025-offline/carry/timing-result.json)和[自检记录](../runs/20261025-offline/checks.json)保留原始数值。手工点属于近似观测；没有接入真实定位服务或自动修改标定通过状态。

## 复现与结果位置

项目已有环境包含 NumPy、SciPy、Pillow，核心流程不需要安装新包。使用新输出目录可以重做一次试验；`collect` 只执行远程标准库文件读取。

```bash
cd /home/wsk/gpt+vla/OpenArmSim
./run offline collect --output runs/离线复验
./run offline fit --output runs/离线复验
./run offline evaluate --output runs/离线复验
```

瓶盖方案使用同一批旧记录，标注随仓库保存在 `reference/cap_points.json`；默认收集器会校验原图摘要。以下命令对应新实验目录：

```bash
.venv/bin/python -B tools/fit_carry_camera.py collect --output runs/离线复验/carry
.venv/bin/python -B tools/fit_carry_camera.py fit --output runs/离线复验/carry
.venv/bin/python -B tools/fit_carry_camera.py evaluate --output runs/离线复验/carry
.venv/bin/python -B tools/fit_carry_camera.py timing --output runs/离线复验/carry
```

`fit` 拒绝覆盖已冻结结果；`evaluate` 拒绝源轨迹、URDF 或拟合点在冻结后发生变化。人工点是近似对应，不具有物理标定资格。

- [报告](../runs/20261025-offline/index.html)：原图叠加、误差图与夹爪曲线。
- [来源](../runs/20261025-offline/data.json)：轨迹哈希、原始时钟、只读核验。
- [参数](../runs/20261025-offline/selected.json)：冻结的候选，`physical_trial_passed=false`。
- [结果](../runs/20261025-offline/camera.json)与[夹爪统计](../runs/20261025-offline/grippers.json)：失败原因和分轨迹数值。
- [标注](../reference/head_points.json)：保存原图像素点及近似性质，后续精标应保留旧版本并使用新实验目录。

图表由已有 OpenPI 环境中的 Matplotlib 生成；数值检查同时使用 OpenCV 独立验证投影公式和已知相机参数恢复。

## 剩余工作

先在旧图像中建立几何定义明确、可重复识别的 CAD 自然特征点，优先改善对应点与参数可辨识性，不要求重新采完整套数据。

腕部相机需要独立的相机到腕部约束；过去的自身夹指轮廓拟合仍是开发候选，不能拿其 IoU 当手眼标定。旧 VR 变换也不能替代相机外参。

抽查四段记录均无深度和力矩。真实夹持力、防滑余量、当前安装是否变化及停止响应，仍需要针对缺项的小范围现场核验。
