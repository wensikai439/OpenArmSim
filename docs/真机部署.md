## r9：现场标定向导与一键运行（2026-10-27）

`handoff/OpenArmRobot-r9.zip` 在 r8 上增加：

- `./run calib`：五步通用标定（markers 打印标记；measure 尺子测量；handeye 手眼、曝光对时、停止保持；grip 只动夹爪测夹持模型、桌面高度和相机能否看到夹住的瓶子；accept 逐项确认）。与具体动作无关，做一次即可。
- 任务位姿在线计算（`app/autoplan.py`，`motion.task_poses=online`）：每次任务开始前按当前观测搜索抓取、交接点、撤离、放置，全部用运行时同一规划器验证，计时在搜索之后才开始。
- `./run grab`（本机 `oa grab`）：预检 → 输入 y 确认现场 → 启动设备服务 → Haiku 执行 → 关闭服务。
- ACT 参考源码改指 `openarm_deploy_bk_20261026`（原目录 10-26 被替换，7 个绑定文件哈希一致）。
- 腕部相机及支架加入碰撞模型；手指碰撞体积按 URDF 全行程扫掠，grip 时用实测张开距离核对。
- 局部逆解失败时，改用 cuRobo V2 做 GPU 全局规划（`app/cumotion.py`，配置 `config/curobo.yml` 由 `python app/cumotion.py build` 从真机 URDF 生成），路径仍需通过同一套 fcl 网格复核；局部规划依次尝试一步求解、直线 2cm 小步逼近，再交给 cuRobo；在线搜索得到的关节构型作为本次会话的 IK 起点（`motion.ik_seeds`）。cuRobo 只安装在 LLMHarness/.venv，记录见 `records/curobo/`。
- fcl 复核改为先用包络凸包快速排除再算精确网格距离，400 组随机姿态判定与旧版完全一致，速度约快 3 倍。
- 背景：ACT 初始姿态下两只手腕的第 7 关节都接近限位，保持朝向时右手往左只能到 y≈-0.06m、左手往右只能到 y≈+0.03m，只靠局部规划接不上交接点。

当前是首次现场准备版本。基础软件回归通过，但合成完整任务仍存在规划失败及预算超时，未跑通完整真机流程。标定初始化保留实测桌面碰撞检查；放置净空按篮口高度计算；规划快照不冒充新鲜执行观测。

## r8

纯真机发行包为 `handoff/OpenArmRobot-r8.zip`，固定 NVIDIA ASPIRE 官方执行器。当前 `relative-bottle/2` 采用连续粗接近、末段约 18 mm 逐步纠偏；每轮核验 ACT 初始姿态，夹稳后停止推进闭爪，确认接收后才松右手。

r8 增加参考 jerk 限制，保留原速度、加速度和增益；按曝光时刻计算手—瓶关系，失败报告保留原始原因。离线参考轨迹对比不等于真机速度、平滑性或成功率验证；单腕全程可见性仍待解决。

它是真机适配版；感知改用真实 RGB-D 注册标记与 FK，没有复制合成相机、虚拟标记、瓶篮尺寸、仿真增益或关节数组。40/40 仿真结果属于源版本，不能当成本适配版真机结果。旧程序在 `app/skill/legacy.py`，旧发行在 `records/versions/`，不自动回退。

环境改为本目录内的 Python 3.10 虚拟环境，只读复用原机器人环境的 OpenCV/ArUco、RealSense、CAN、NumPy、SciPy；新增 FCL 安装仅在此虚拟环境。同一 API 配置原样保留，不复制或打印密钥。

```sh
./run prepare deps
./run check
./run verify
./run relative
./run preflight
./run service
./run chat "检查真实服务准备情况，不要运动"
```

上述检查不启动设备。`service` 默认是无设备服务；只有经过独立实测验收并显式选择设备会话，才允许真实动作。标定与碰撞配置可以独立维护，验收绑定代码、参数与几何摘要；修改后旧验收失效。
