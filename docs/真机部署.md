# OpenArm 接入包

本包包含仿真、harness、反馈恢复 skill，以及本地状态回放和影子规划入口。当前没有瓶/篮三维感知服务，也没有可执行真机运动的工具适配器，因此这是**接入准备包**，尚未通过真机迁移验收。这轮没有连接、上传或修改公司电脑，没有打开相机、CAN 或机械臂。

## 解压使用

需要 Ubuntu、Python 3.11 和可用的 MuJoCo EGL/桌面渲染。将 ZIP 和校验文件放到同一空目录：

```sh
sha256sum -c OpenArmSkill-20261024-v2.sha256
unzip OpenArmSkill-20261024-v2.zip
cd OpenArmSim
chmod +x run
python3.11 -m venv .venv
.venv/bin/python -m pip install -r deploy/requirements.txt
.venv/bin/python -B tools/verify_handoff.py
./run aspire recover --fault receiver_close_loss
./run real preflight
./run real replay --episode 0
./run real demo
./run start
```

网页：`http://127.0.0.1:8767/`。`recover` 是独立仿真任务；`demo` 是明确标为 synthetic_fixture 的影子规划自检。两者都不操作机器人，也不需要 API。打包后的首次环境安装仍需在接收者电脑上完成；本机解压验收复用本机依赖，不等于已验证所有新系统/显卡组合。

API 只在需要模型开发/修订或网页智能体时另行配置。密钥没有打包。冻结 skill 本身可不调用 API，按实际工具反馈选择分支。ACT、π0.5 的权重、独立推理环境及公司系统依赖均未打包。

## 各入口实际做什么

| 命令 | 行为与边界 |
|---|---|
| `./run aspire recover` | 运行新版反馈恢复 skill；场景位姿来自仿真几何真值 |
| `./run aspire recover --fault stale_grasp` | 一次合成高度偏差，验证实际撤离、重提议和重抓；不是视觉定位测试 |
| `./run real preflight` | 检查本地 skill 哈希、能力和待补接口；不会导入硬件控制器 |
| `./run real replay --episode 0` | 读取包内以前导出的真实关节/夹爪与记录时间；只显示状态，不执行动作 |
| `./run real demo` | 合成快照 → 相同 skill/ASPIRE 执行器 → 抓姿/路径提案；执行前停止，运动命令为0 |
| `./run real shadow --observation 文件.json` | 校验实测快照并做下一阶段影子规划；没有实测输入时明确 blocked |

影子规划得到的关节路径不是执行命令。它没有模拟完整任务成功，也没有用预测接触代替真实夹持。默认 `deploy/observation.example.json` 的位置、状态和夹持证据为空，拒绝规划是正常结果；不能填入仿真真值并声称是真实观测。

## 新版 skill 修了哪里

开发反例显示：带载放置的关节插值产生夹持中断；失败恢复曾调用旧撤离路径，与正常现代交接的归位路径不一致。仅降速未修复全部反例。

新版按瓶体位置和朝向插入连续小段目标，每段用最新手—瓶关系重新规划；恢复交接在确认双方夹持、松右手后，执行现代交接的受检空手归位。原生碰撞、持续双指接触、放置/释放/稳定条件和原120秒预算保留。改进来自工具与执行层工程，未训练新的神经模型，也没有证明 LLM 优于相同工具上的强规则策略。

目标计算与碰撞预测使用同一份新测手—瓶关系。中间航点6mm比原运输段12mm更严格，最终下降仍遵守3mm请求；没有通过放宽最终验收来提高成功率。分段运动仍比原宏动作慢。

`skills/bottle_recovery/` 是当前技能，`history/v1/` 保留前版。旧 `bottle_relay` 和固定 TAMP 演示未替换。统计见 `evidence/20261024-precision/final/assessment.json`；开发失败与泛化测试分开，区域采样不代表连续工作空间保证。仿真仍使用候选模型及几何真值，规划期间时钟暂停。

## 未来的实测快照

复制 `deploy/observation.example.json`，由真实感知/状态服务填写。接入时不需要改 skill 的动作分支。

- `source=measured_perception`，`frame=robot_base`，时间为同步的 Unix 秒，必须对应当前曝光/状态。
- 16维状态顺序为左7关节、左夹爪、右7关节、右夹爪，单位rad。动作夹爪与反馈映射须独立确认，不把训练数据范围当作物理标定。
- 瓶/篮位姿用 `model_origin` 参考点、xyzw四元数，并提供位置不确定度。检测中心需要物体参考点变换，不能冒充模型原点。
- 两手需要实测的 empty/holding/unknown 证据及来源；闭爪不等于持瓶。当前入口只接受有证据的空手起点。
- `deploy/config.json` 的基座到仿真世界变换仍为软件对齐候选。200ms、5mm仅为接入检查示例门槛，不是实测精度保证。

影子规划只初始化一个独立规划模型；不会回写真实状态、访问设备、发控制指令或在预测动作后伪造持瓶状态。模型中的瓶/篮和指爪几何仍需与真机测量对齐。

## 真机运动前尚需补齐

1. 实现感知/状态接口，确认相机内外参、TCP、关节零位、基座/桌面尺寸、夹爪传动、瓶/篮几何和时钟；用独立样本验证。
2. 将13个工具的实际执行接到已确认的轨迹控制器、实时反馈和看门狗，保持同样的前置条件、错误码和阶段边界。LLM 不写 CAN，不发高频控制。
3. 真实夹持、交接双方持瓶、供物手脱离和入篮支撑均来自真实证据。仿真分数、旧记忆和“指令已发出”不能代替成功。
4. 操作员在场并单独授权实机动作后，分别验收低速空手到位、抓瓶持稳、交接、放置和失败停止，再做配对 sim/real 新位置测试。

本包没有 `real execute` 命令。把 `hardware_enabled` 改为true只会被拒绝，不能解锁运动。包内 `reference/source/inputs/controller.py` 是获授权导出的参考源码；其构造器会使能电机并发指令，不能把实例化它当只读检查。本接入入口不会导入它。

## 版本与复验

`PACKAGE-MANIFEST.json` 记录来源提交、逐文件SHA-256、官方 ASPIRE 版本及缺失的真机能力。`tools/verify_handoff.py` 验证完整性和一条仿真结构转移，不代表任务或物理标定成功。`evidence/` 按实验名称分开保存协议与统计，避免混淆结论。

包内包含已获授权导出的内部参考源码/数据，仅在团队已有权限范围流转；没有密钥、权重、虚拟环境、数据库、大体积原始实验、缓存或 Git 历史。再打包时先提交已验证代码，再指定新文件名运行 `./run aspire package --output handoff/新名称.zip`；已有包不会覆盖。

方法参考：[NVIDIA ASPIRE](https://github.com/NVlabs/ASPIRE) 的开发失败迭代与技能复验，以及 [MoveIt Task Constructor](https://moveit.picknik.ai/main/doc/tutorials/pick_and_place_with_moveit_task_constructor/pick_and_place_with_moveit_task_constructor.html) 的分阶段候选和连接检查。本项目是 OpenArm 自定义适配，不是原论文基准的完整复现。
