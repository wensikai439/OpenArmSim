## 公司电脑

唯一可写位置：`/home/sj/Desktop/wuji/lerobot_20260116/LLMHarness/`。所有新源码、环境、下载、缓存、配置和记录都留在这里。现有 `openarm_deploy/`、权重、控制代码和 Conda 环境只读；部署不会改原模型启动流程。

进入该目录后：

```sh
./run help
./run verify
./run status
./run aspire recover
./run aspire recover --fault receiver_close_loss
./run real replay --episode 0
./run real demo
./run check
```

`recover` 在独立 MuJoCo 仿真中执行完整任务，不访问真机，不调用 API。`real demo` 使用明确标为 `synthetic_fixture` 的合成快照，只计算下半瓶身预抓取路径，然后在执行前停止；运动命令和物理推进步数均为0。它不代表真机任务完成。

公司目录版替换了启动入口，禁止原有用户级 systemd、全局 API 密钥环、训练及真机执行命令。无定时任务或开机自启。源码和 API 开发模块仍在包里，但未给公司目录入口开放。该入口用于避免误调用，不是能约束任意 Python 代码的操作系统安全沙箱。详见 `deploy/REMOTE.md`。

## 交接包

`OpenArmSkill-20261024-v3-remote.zip` 是公司目录限定入口，不能使用旧v2包的启动说明。包不含密钥、权重、虚拟环境、数据库、Git 历史或大型原始录像。内部参考源码/数据仅供团队在已有权限范围使用。

普通包需要 Python 3.11 或 3.12：解压后创建 `.venv`，安装 `deploy/requirements.txt`，再运行 `.venv/bin/python -B tools/verify_handoff.py`。公司版已经在指定目录内准备独立环境，不安装或修改系统包。`PACKAGE-MANIFEST.json` 记录来源提交、逐文件校验和、技能版本和目录部署类型；`third_party/aspire/ORIGIN.json` 记录官方运行时来源与校验和。

再打包前先提交已验证代码：

```sh
./run aspire package --output handoff/新版本.zip
# 公司目录版，需显式开启限定入口：
.venv/bin/python -B -m tools.package_skill --confined --output handoff/公司版.zip
```

## 已实现与缺少的接口

| 入口 | 实际能力 |
|---|---|
| `real preflight` | 核对程序和运行时哈希，报告实测接口缺项 |
| `real replay` | 读取此前导出的关节/夹爪和时间记录，不发送动作 |
| `real demo` | 相同 v3 skill、14工具和官方执行器的合成影子规划 |
| `real shadow --observation 快照.json` | 校验新鲜实测输入并生成下一阶段提案，不发送动作 |

`deploy/observation.example.json` 是空模板，拒绝规划属于预期行为。实测输入必须提供 `robot_base` 坐标系、同步 Unix 时间、16维状态（左7关节、左夹爪、右7关节、右夹爪）、瓶篮模型原点位姿/不确定度、左右手真实夹持证据。仿真真值不能伪装成实测输入，闭爪不能代替持瓶证据。

目前没有真实瓶篮三维位姿/夹持服务，也没有将14个工具接到真机轨迹控制器的执行适配器。因此这是安装完成后可离线验收的接入部署，不是解压即可抓瓶的真机控制系统。`hardware_enabled` 必须为false，没有 `real execute` 命令。真实标定、夹爪/动作语义、控制时序、实时反馈和看门狗仍需补齐；仿真负载补偿使用候选模型参数，不能直接用于真机。

参考控制器的构造器会使能电机，不得为只读检查而导入实例化它。首次真机运动需要操作员在场，先低速空手分段验收，再进行持瓶、交接、入篮和失败停止；安装、仿真通过及回放都不能替代这些验收。

参考：[NVIDIA ASPIRE](https://github.com/NVlabs/ASPIRE)、[固定版本执行器](https://github.com/NVlabs/ASPIRE/blob/fa00f0ef2bc1d91d594b9aa502c22133c9f538f7/src/cap_harness/runtime.py)。
