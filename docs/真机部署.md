## 当前版本

纯真机发行包为 `handoff/OpenArmRobot-r7.zip`，固定 NVIDIA ASPIRE 官方执行器。当前 `relative-bottle/1` 参考本地 adaptive v4：按当前瓶子/篮子与实际手位计算目标，最终接近与放置下降最多每步 6 mm，接收夹稳后才松右手并撤离。

它是真机适配版；感知改用真实 RGB-D 注册标记与 FK，没有复制合成相机、虚拟标记、瓶篮尺寸、仿真增益或关节数组。40/40 仿真结果属于源版本，不能当成本适配版真机结果。旧程序在 `app/skill/legacy.py`，旧发行在 `records/versions/`，不自动回退。

环境改为本目录内的 Python 3.10 虚拟环境，只读复用原机器人环境的 OpenCV/ArUco、RealSense、CAN、NumPy、SciPy；新增 FCL 安装仅在此虚拟环境。同一 API 配置原样保留，不复制或打印密钥。

```sh
./run prepare deps
./run check
./run verify
./run relative
./run preflight
./run service
./run chat "检查真实服务准备情况，不要运动"
```

上述检查不启动设备。`service` 默认是无设备服务；只有经过独立实测验收并显式选择设备会话，才允许真实动作。标定与碰撞配置可以独立维护，验收绑定代码、参数与几何摘要；修改后旧验收失效。

## 证据范围

本地/远程无设备回归包含慢滑、日志失败、保护检查异常、阻塞反馈、错误规划结果、会话争用、初始化前的路径拒绝，以及冻结程序的正常流程/接收恢复。真实 URDF 与网格仅用于离线几何/IK检查，不代表已经完成实物抓取。

SDK 已成功导入；实际相机、CAN 和电机未启动。仍需现场测量相机外参/曝光对时、物体与夹爪几何、夹持阈值和相对抓姿，并完成分段动作与硬件看门狗验收。原始 URDF 的 0.3 mm 占位碰撞球不能替代这些工作。

相对参数集中在 `config/calibration.json → motion.relative`：纠偏上限已配置；初始双手中点到安全交接点的偏移和右手撤离向量待实测，不猜填。其余相机、夹持、几何、工作空间和物理验收仍由 `preflight` 严格检查。

公司端入口、数据采集与现场步骤见 [部署说明](../deploy/ROBOT.md) 和 [试运行](../deploy/试运行.md)。本轮发布、检查及原文件保护证据保存在 `runs/20261026-deploy/` 与公司端 `records/`。只有实测结果才能更新真机成功标记。
