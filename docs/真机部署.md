# 抓瓶技能与真机部署

本包用于复现仿真结果、开发真机适配器和准备分阶段验收。**包内没有可操作真机的驱动，当前技能尚未通过真机迁移。** 公司 SSH 电脑本轮没有被修改，也没有启动相机、CAN 或机械臂。

## 先在本地使用

环境要求为 Ubuntu、Python 3.11 和可用的 MuJoCo EGL/桌面渲染。解压后进入 `OpenArmSim`：

```sh
sha256sum -c OpenArmSkill-20261024.sha256  # 在 ZIP 所在目录执行
python3.11 -m venv .venv
.venv/bin/python -m pip install -r sim/requirements.txt
.venv/bin/python -B tools/verify_handoff.py
./run aspire test --x .52 --y -.20
./run aspire prepare
./run start
```

网页地址为 `http://127.0.0.1:8767/`。`test` 使用冻结程序和官方 ASPIRE 执行器，**不用 API，也不连接真机**。`prepare` 的默认模板会列出缺项并返回退出码 2，这是接口尚未完成的正常结果；它不会启用运动。ACT、π0.5、cuRobo 的权重和独立环境未打包，也不是本技能运行的必需项。

包内自带固定版本的官方 ASPIRE `cap_harness` 源码、LICENSE、NOTICE 和来源提交，避免依赖原作者电脑上的绝对路径。安装流程尚需在同事的新机器上确认显卡驱动；干净解压验收复用了本机 Python 环境，不能当成全新系统安装验证。

## 这次增强了什么

技能按当前持瓶状态选择下一步：无人持瓶时右手抓取；右手已持瓶时开始交接；左手已持瓶时开始放置。每段动作后重新观测，工具失败、双手状态不明确或持瓶证据不符时终止，不盲目重试、松手或自动重置。

底层新选项包括：

- `handover(..., placement_aware=True)`：接收手的抓姿需要同时满足篮子放置端点和下降连接的几何检查；接收手实际夹稳后，供物手才松开。
- `place(..., shape_clearance=True)`：用当前手—瓶关系重新选择直立的瓶体放置姿态，检查携物接近和下降路径；离散朝向之外提供连续自由 yaw 提案。

物体仍为自由刚体，运动通过原生执行器和接触产生。没有修改质量/摩擦等标称物理参数来掩盖失败，也没有放宽原来的碰撞、入篮、支撑、脱离夹爪或稳定条件。原来的固定 TAMP 演示保留。测试中的质量/摩擦变化是每个新实例的初始压力条件，两个版本使用相同条件；不能把它们叫作实测标定。

**泛化来源是当前几何上的规划与闭环检查，加上工程改进后的技能组合。这里没有训练 ACT/π0.5 权重，也不能归因成 LLM 自己学会了新的物理控制。** 范围仍是同一已登记直立瓶子、现有机器人和篮子，尚不支持任意物体、倒瓶、遮挡、视觉定位误差或任意位置。

逐例结果和冻结输入见包内 `evidence/`；本机完整原生轨迹在 `runs/20261024-relay/`。未通过的案例必须计入报告，不得只挑成功视频。

## 真机需要补上的接口

仿真程序可以保持不变，需要替换的是注册工具的实现。LLM 不直接写 CAN，也不发高频关节命令。

```text
LLM / 任务入口
  → 读取 skill 与能力契约，选择技能
  → ASPIRE ProgramExecutor：执行冻结 program.py
  → get_observation / pick / handover / place
  → 真实感知、TAMP/运动规划、执行控制器、看门狗
  → OpenArm
```

| 仿真接口 | 真机适配器必须提供的内容 |
|---|---|
| `get_observation()` | 相机测得的瓶/篮位姿、时间戳、基座坐标系、位姿不确定度、左右手持瓶证据；不能返回 MuJoCo 真值或旧记忆坐标 |
| `pick()` | 当前物体几何/抓姿候选、碰撞规划、实际闭爪与抬升、夹持验证；夹爪闭合不等于抓住 |
| `handover()` | 供物手/接收手身份、双臂碰撞和下游放置检查、双手持稳、供物手松开和撤离的分阶段反馈 |
| `place()` | 从实测手—瓶关系推导携物路径、瓶体实际到位、低速释放、夹爪撤离和连续稳定验证 |
| 工具回执 | `.ok`、执行步数、错误码、当前持瓶手和观测版本；超时、对象丢失或反馈缺失不得上报成功 |

同名接口不代表驱动已经兼容。真机侧要重新实现上述能力，并对齐模型、坐标系、碰撞几何、关节零位、夹爪量纲、重力补偿和控制周期。不能把 MuJoCo 原生目标、参考轨迹或仿真规划得到的关节数组直接发送给真机。

`skills/bottle_relay/robot.example.json` 是不含密钥的接口清单。复制为团队自己的配置后填写关节顺序、真实夹爪命令范围、控制频率、驱动实现、标定与配对试验文件哈希。示例里的 5 mm、200 ms 只是待验证的准备阈值，不是已经证明满足的硬件指标。配置完整也不等于通过物理验收；`prepare` 只核对声明和文件哈希。

## 推荐的真机接入顺序

1. **先读数对齐。** 核对机器人/URDF 版本、14 个关节顺序和零位、左右夹爪命令与编码器映射、控制周期及反馈时钟。在机器人不运动的情况下，对比真实关节 FK、相机中末端与瓶/篮位置。腕部相机需要随关节更新外参。
2. **再做观测回放与影子规划。** 把真实 RGB、时间戳、状态和标定数据交给感知/规划，只输出候选和诊断，不发动作。随机摆放多个瓶子位置，检查可达性、桌面/篮沿/对侧手臂间隙，以及感知丢失时是否停止。
3. **分别验收三个原语。** 在操作员在场、急停可用、经单独授权的条件下，先低速空手到位，再右手抓起并持稳，再双手交接，最后左手放篮。速度和关节步长由实机控制契约确定，不照搬仿真常数。双手交接必须在供物手未松开时确认接收手夹持。
4. **最后做完整闭环。** 固定一组真实起点，保存时间同步的相机、指令、反馈、工具回执和失败原因。与对应仿真初始条件成对比较。先测试少量位置，再扩大摆放区域；碰撞、掉瓶、反馈缺失、位姿过期和交接证据不足都算失败/停止。
5. **扩大真实验证范围后再称为迁移。** 真实位置测试与用于调试的位置分开。记录抓取、交接、入篮分阶段成功率及完整任务成功率。先暴露系统误差，再决定是修标定、控制器、抓姿搜索，还是补数据训练 VLA。

第一次真机试验仍需要：机器人/控制器版本与安装尺寸、相机内外参与时钟对齐、TCP/夹爪开度实测、瓶/篮尺寸和质量、可用驱动入口，以及操作员在场。现有记录可以核对接口、建立候选模型，不能替代这些独立测量。

## 重新打包与版本管理

在项目里完成验收并提交代码后运行：

```sh
./run aspire package
```

包生成在 `handoff/`，附 SHA-256 文件和逐文件 `PACKAGE-MANIFEST.json`。压缩包保留 frozen skill、harness、MuJoCo 模型、简短测试证据、少量既有参考数据和官方运行时；排除个人 API 配置、密钥、权重、虚拟环境、数据库、缓存、Git 历史和大体积原始实验。

交接包包含已获授权导出的内部参考源码/数据，仅按团队已有权限流转。当前没有向公司 SSH 主机上传任何内容。待真实适配器及标定验收完成，再另做包含驱动与已验证配置的部署版本，并让它默认只读/禁用运动；操作员明确启用后才允许真实执行。

设计参考：[NVIDIA ASPIRE](https://github.com/NVlabs/ASPIRE) 的技能迭代与独立复验，以及 [MoveIt Task Constructor](https://moveit.picknik.ai/main/doc/tutorials/pick_and_place_with_moveit_task_constructor/pick_and_place_with_moveit_task_constructor.html) 的候选、阶段连接和下游可行性约束。本项目使用自定义 OpenArm 适配器，不等同于原论文基准复现。
